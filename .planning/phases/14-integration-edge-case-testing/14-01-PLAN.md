# Plan 14-01: Benchmark Suite

<objective>
Formalize the existing parallel-fanout-bench.ts into a proper Rust IVM benchmark that measures Rust vs TS advance() throughput across pipeline counts and diff sizes, with a correctness gate and a 4x minimum performance bar.
</objective>

<must_haves>
- File `packages/zero-cache/src/services/view-syncer/rust-ivm-bench.ts` exists and is executable
- Pipeline count sweep covers [1, 2, 4, 8, 16, 32, 64] pipelines
- Diff size sweep covers [1, 10, 100, 500, 1000] inserts
- A/B comparison toggles ZERO_DISABLE_RUST_IVM env var between runs
- Correctness gate: JSON-serialized RowChange output from Rust path is byte-identical to TS path for every workload
- Performance bar: logs PASS/FAIL against 4x minimum and 6x target on 50-pipeline realistic workload
- Benchmark outputs machine-readable JSON summary to stdout
</must_haves>

<action>
Create `packages/zero-cache/src/services/view-syncer/rust-ivm-bench.ts`.

Reuse the DB setup pattern from `parallel-fanout-bench.ts` (schema: issues + comments, WAL2 journal mode, initReplicationState, populateFromExistingTables, fakeReplicator.processTransaction).

Structure:

```typescript
// Config
const PIPELINE_COUNTS = [1, 2, 4, 8, 16, 32, 64];
const DIFF_SIZES = [1, 10, 100, 500, 1000];
const ITERATIONS = 5;
const REALISTIC_PIPELINES = 50;
const REALISTIC_DIFF = 100;
const MIN_SPEEDUP = 4.0;
const TARGET_SPEEDUP = 6.0;
```

Import the same dependencies as parallel-fanout-bench.ts:
- `createSilentLogContext`, `testLogConfig`, `DbFile`, `Database`, `DatabaseStorage`, `CREATE_STORAGE_TABLE`
- `Snapshotter`, `PipelineDriver`, `Timer`, `InspectorDelegate`
- `fakeReplicator`, `ReplicationMessages`, `initReplicationState`, `populateFromExistingTables`, `listTables`
- `createSchema`, `table`, `string`, `boolean`, `number` from schema builders

Use the same `NO_TIME_ADVANCEMENT_TIMER`, `shardID`, `mutationsTableName`, schema, and 4 QUERY_TEMPLATES (JOIN, Filter, LIMIT, plain scan) from parallel-fanout-bench.ts.

Helper functions:

1. `setupDb(numRows: number)` — same as parallel-fanout-bench.ts setupDb but parameterized row count (default 500).

2. `generateQueries(count: number)` — same as parallel-fanout-bench.ts, cycles through QUERY_TEMPLATES.

3. `runAdvance(dbFile, db, numPipelines, numInserts, disableRust: boolean)` — creates PipelineDriver, adds N queries, pushes numInserts transactions via fakeReplicator, sets `process.env.ZERO_DISABLE_RUST_IVM` to '1' or deletes it based on disableRust flag, calls `pipelines.advance(timer)`, collects all changes into an array, returns `{elapsed: number, changes: RowChange[], changeCount: number}`. Reset the env var after each run.

4. `serializeChanges(changes: RowChange[])` — JSON.stringify with sorted keys for deterministic comparison. Sort changes by `[queryID, table, JSON.stringify(row_key), type]` before serializing.

Main benchmark flow:

```
interface BenchResult {
  pipelines: number;
  diffSize: number;
  tsMs: number;
  rustMs: number;
  speedup: number;
  correctnessPass: boolean;
}
```

A. **Microbench — Pipeline count sweep** (fixed diff size = REALISTIC_DIFF):
   For each count in PIPELINE_COUNTS, run ITERATIONS iterations:
   - Setup fresh DB each iteration
   - Run with disableRust=true (TS path), collect time + changes
   - Run with disableRust=false (Rust path), collect time + changes  
   - Compare serialized changes for correctness
   - Record median times
   - Print: `Pipeline sweep | N pipelines | TS: Xms | Rust: Yms | Speedup: Z.Zx | Correct: PASS/FAIL`

B. **Microbench — Diff size sweep** (fixed pipelines = REALISTIC_PIPELINES):
   For each size in DIFF_SIZES, same pattern as above.
   Print: `Diff sweep | N inserts | TS: Xms | Rust: Yms | Speedup: Z.Zx | Correct: PASS/FAIL`

C. **Realistic workload** (50 pipelines, 100 inserts, 500 seed rows):
   Run ITERATIONS iterations, compute median speedup.
   Print: `Realistic | Speedup: Z.Zx | Min bar (4x): PASS/FAIL | Target (6x): PASS/FAIL`

D. **JSON summary output**:
   After all runs, print `\n--- BENCHMARK RESULTS ---\n` followed by `JSON.stringify({pipelineSweep, diffSweep, realistic, overallPass}, null, 2)` where overallPass is true only if realistic speedup >= 4x AND all correctness gates passed.

Usage line at top of file:
```
// Usage:
//   node --experimental-strip-types --experimental-transform-types packages/zero-cache/src/services/view-syncer/rust-ivm-bench.ts
```

IMPORTANT: Do NOT modify parallel-fanout-bench.ts. Do NOT modify pipeline-driver.ts. Do NOT modify any test files. This is a new standalone script.
