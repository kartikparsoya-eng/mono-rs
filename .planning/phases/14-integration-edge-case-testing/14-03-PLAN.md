# Rust IVM Architecture

## Overview

Brief description: Phases 10-13 ported the IVM hot path (filter, take, join, exists operators + parallel fan-out) from TypeScript to Rust via napi-rs. The Rust path handles all SQLite I/O and row-level computation, delivering 5-10x throughput improvement.

## Components

### Rust Crates
- `zqlite-rs` (packages/zqlite-rs/) — napi-rs native module
  - `advance.rs` — Rayon fan-out coordinator, predicate evaluation, pipeline processing
  - `diff.rs` — Diff reader (reads _zero.changeLog2, fetches prev/curr row snapshots)
  - `database.rs`, `statement.rs` — SQLite Database/Statement wrappers
  - `types.rs` — Row-to-JS conversion, type coercion
- `zero-ivm-rs` (packages/zero-ivm-rs/) — Standalone IVM operators (filter, take, join, exists)

### TypeScript Integration Layer
- `pipeline-driver.ts` — Orchestrates IVM pipeline, routes to Rust or TS path
- `rust-filter.ts`, `rust-take.ts`, `rust-join.ts`, `rust-exists.ts` — Thin TS wrappers delegating to napi-rs

## Data Flow

Describe the flow:
1. Replicator writes changes to SQLite + `_zero.changeLog2`
2. `pipeline-driver.ts` calls `rust_advance()` (or TS advance if Rust disabled)
3. `rust_advance()` opens two read-only SQLite connections (prev/curr snapshots)
4. `diff.rs` reads changelog, fetches row data from both snapshots
5. `advance.rs` fans out changes across pipelines via Rayon `par_iter()`
6. Each pipeline applies filter/take/join/exists operators
7. Results serialized as JSON, returned to TS, converted to RowChange objects

## Operator Boundary

Explain which operators run in Rust vs TS:
- Rust: filter (predicate eval), take (sort + limit), join (child fetch + overlay), exists (relationship size check)
- TS fallback: any pipeline with unsupported operator combinations, `related` subqueries not handled by Rust join

## Fallback Mechanisms

Document all fallback triggers:
- `ZERO_DISABLE_RUST_IVM=1` env var
- Native module not built (rustAdvanceFn undefined)
- Pipeline not eligible (has unsupported operators)
- Not all pipelines eligible (mixed topology)
- Rust advance throws error → catches, logs warning, falls back to TS
- version_mismatch → retry once with fresh snapshot
- reset/truncate → throw ResetPipelinesSignal
```

Keep the document concise (200-300 lines). Use code references with file paths. No ASCII diagrams needed — text descriptions are fine.

# Rust IVM Operations Guide

## Prerequisites

- Rust toolchain (rustup, cargo) — required to build zqlite-rs native module
- Node.js 20+ with napi-rs support
- SQLite with WAL2 support (bundled via @rocicorp/zero-sqlite3)

## Building

    cd packages/zqlite-rs && npm run build

This runs `cargo build --release` and produces the native module.

## Enabling/Disabling Rust IVM

| Env Var | Effect |
|---------|--------|
| `ZERO_DISABLE_RUST_IVM=1` | Disables all Rust paths, forces TS fallback |
| (unset) | Rust paths enabled when native module is available |

The Rust path is automatically used when:
1. The native module is built and loadable
2. All pipelines in the driver are Rust-eligible
3. ZERO_DISABLE_RUST_IVM is not set

## Monitoring

- Rust advance logs timing via OpenTelemetry spans
- Fallback events logged at WARN level with reason
- If Rust advance throws, the driver logs a warning and permanently falls back to TS for that session

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| "Failed to load native module" | zqlite-rs not built | Run `cd packages/zqlite-rs && npm run build` |
| Rust path not activating | Mixed eligible/ineligible pipelines | Check pipeline topology — joins/limits may force TS path |
| version_mismatch errors | Snapshot lag | Usually self-healing (retries once). If persistent, check replicator health |
| Performance below 4x | Insufficient parallelism | Ensure >4 pipelines and >1 CPU core available |

## Rollback

Set `ZERO_DISABLE_RUST_IVM=1` to immediately disable all Rust paths without redeployment.
```

Keep concise (100-150 lines).
