# Plan 01-02: Implement Database + Statement Classes in Rust

<objective>
Implement the core Rust Database and Statement napi-rs classes with rusqlite, matching the API surface of `db.ts`. Database supports open, exec, pragma, close, transaction, compact, unsafeMode. Statement supports run, get, all, iterate with exact type coercion matching better-sqlite3. Includes Rust unit tests for edge cases.
</objective>

<must_haves>
- [ ] Rust `Database` class exported via napi with: constructor(path, options), exec, pragma, prepare, close, transaction, compact, unsafeMode, name getter, inTransaction getter
- [ ] Rust `Statement` class exported via napi with: run, get, all, iterate, safeIntegers
- [ ] Rust `RowIterator` class for lazy row iteration with next()/return()
- [ ] SQLite→JS type coercion: NULL→null, INTEGER→number (or bigint with safeIntegers), REAL→number, TEXT→string, BLOB→Buffer
- [ ] RunResult returned as `{changes, lastInsertRowid}` object
- [ ] Rust `#[cfg(test)]` unit tests for type coercion, NULL handling, transactions, error cases
- [ ] `cargo test` passes with all unit tests green
</must_haves>

```rust

use std::sync::Arc;
use napi::*;
use napi_derive::napi;
use rusqlite::{Connection, OpenFlags};

#[napi]
pub struct Database {

    page_size: i64,
}
```

Implement methods matching `db.ts` API:

1. **`#[napi(constructor)] fn new(path: String, options: Option<DatabaseOptions>) -> napi::Result<Self>`**
   - `options` includes `readonly: bool`, `fileMustExist: bool`
   - Map options to `OpenFlags`: readonly → `SQLITE_OPEN_READ_ONLY`, fileMustExist → omit `SQLITE_OPEN_CREATE`
   - Default: `SQLITE_OPEN_READ_WRITE | SQLITE_OPEN_CREATE`
   - Special case: `":memory:"` → `Connection::open_in_memory()`
   - Read `PRAGMA page_size` immediately after open
   - On error: return `napi::Error` with message (TS wrapper creates `DatabaseInitError`)

2. **`#[napi] fn exec(&self, sql: String) -> napi::Result<()>`**
   - `self.conn.borrow().execute_batch(&sql)?`
   - On SqliteError: append sql to message before returning

3. **`#[napi] fn pragma(&self, env: Env, sql: String) -> napi::Result<JsUnknown>`**
   - Execute `PRAGMA {sql}` and return array of row objects
   - Use `conn.prepare()` + `query_map()` to get rows
   - Return as `Vec<JsObject>` (array of {column: value} objects)

4. **`#[napi] fn prepare(&self, sql: String) -> napi::Result<Statement>`**
   - Create `Statement` with `Arc<RefCell<Connection>>` clone + sql string
   - Statement validates SQL by calling `conn.prepare()` (catches syntax errors early)

5. **`#[napi] fn close(&self) -> napi::Result<()>`**
   - Run `PRAGMA optimize` if not readonly
   - Drop the connection (or explicit close)

6. **`#[napi] fn transaction(&self, env: Env, callback: JsFunction) -> napi::Result<JsUnknown>`**
   - Begin transaction on connection
   - Call JS callback
   - If callback succeeds: commit
   - If callback throws: rollback, re-throw

7. **`#[napi] fn compact(&self, freeable_bytes_threshold: f64) -> napi::Result<CompactResult>`**
   - Check `PRAGMA freelist_count`
   - Check `PRAGMA auto_vacuum` == 2 (incremental)
   - Run `PRAGMA incremental_vacuum` if threshold met
   - Return `CompactResult { compacted: bool, freed_bytes: f64 }` (TS wrapper handles logging)

8. **`#[napi] fn unsafe_mode(&self, unsafe_val: bool) -> napi::Result<()>`**
   - Map to SQLite pragmas: `PRAGMA synchronous = OFF` and `PRAGMA journal_mode = OFF` when unsafe
   - Or use `PRAGMA trusted_schema` equivalent

9. **`#[napi(getter)] fn name(&self) -> String`** — return path

10. **`#[napi(getter)] fn in_transaction(&self) -> bool`** — `!conn.is_autocommit()`

Include `#[napi] struct DatabaseOptions { readonly: Option<bool>, file_must_exist: Option<bool> }`.

Create `packages/zqlite-rs/src/statement.rs`:

```rust
#[napi]
pub struct Statement {
    conn: Arc<RefCell<Connection>>,
    sql: String,
    safe_integers: bool,
}
```

**Key design:** Statement does NOT hold a rusqlite::Statement (which borrows Connection). Instead it stores the SQL string and re-prepares via `conn.prepare_cached()` on each call. rusqlite's internal cache makes re-preparation nearly free.

Methods:

1. **`#[napi] fn safe_integers(&mut self, use_big_int: bool) -> napi::Result<&Self>`**
   - Set `self.safe_integers = use_big_int`
   - Return `self` for chaining (napi-rs supports `&Self` returns as `this`)

2. **`#[napi] fn run(&self, env: Env, params: Vec<JsUnknown>) -> napi::Result<JsObject>`**
   - `conn.borrow().prepare_cached(&self.sql)?.execute(params)?`
   - Return `RunResult` object: `{changes: conn.changes(), lastInsertRowid: conn.last_insert_rowid()}`
   - `lastInsertRowid` follows `safe_integers` flag (number or bigint)

3. **`#[napi] fn get(&self, env: Env, params: Vec<JsUnknown>) -> napi::Result<JsUnknown>`**
   - `prepare_cached` + `query_row()` 
   - Return single row as JS object, or `null` if no rows

4. **`#[napi] fn all(&self, env: Env, params: Vec<JsUnknown>) -> napi::Result<Vec<JsObject>>`**
   - `prepare_cached` + `query_map()` + collect
   - Return array of row objects

5. **`#[napi] fn iterate(&self, env: Env, params: Vec<JsUnknown>) -> napi::Result<RowIterator>`**
   - Create RowIterator that lazily fetches rows
   - RowIterator holds its own prepared statement (materialized from SQL)

<action>
Create `packages/zqlite-rs/src/row_iterator.rs`:

The iterator pattern is the trickiest part due to rusqlite's borrow semantics. Two approaches:

**Approach A (Recommended): Materialize-on-create with lazy JS conversion**
- When `iterate()` is called, execute the query and collect all rows as `Vec<Vec<rusqlite::types::Value>>` in Rust
- RowIterator holds this Vec and an index
- `next()` converts one row at a time to JS objects
- Pro: No lifetime issues. Con: Memory for all rows upfront (but no JS object creation cost until iterated)

**Approach B: True lazy with raw pointers**
- Store raw `*mut sqlite3_stmt` and advance per `next()` call
- Requires unsafe code. Not recommended for Phase 1.

Implement Approach A:

```rust
#[napi]
pub struct RowIterator {
    rows: Vec<Vec<rusqlite::types::Value>>,
    columns: Vec<String>,
    index: usize,
    safe_integers: bool,
}

#[napi]
impl RowIterator {
    #[napi]
    pub fn next(&mut self, env: Env) -> napi::Result<JsObject> {
        // Return {value: row_object, done: false} or {value: undefined, done: true}
        let result = env.create_object()?;
        if self.index < self.rows.len() {
            let row = &self.rows[self.index];
            self.index += 1;
            let obj = values_to_js_object(&env, row, &self.columns, self.safe_integers)?;
            result.set("value", obj)?;
            result.set("done", false)?;
        } else {
            result.set("value", env.get_undefined()?)?;
            result.set("done", true)?;
        }
        Ok(result)
    }
}
```

**Make RowIterator implement JS iterator protocol:**
- The TS wrapper will add `[Symbol.iterator]` returning `this`
- `next()` returns `{value, done}` — standard iterator protocol
