# Plan 13-02: Rayon Fan-out Coordinator

## Objective

Create the `rust_advance()` napi function in `zqlite-rs` that drives the full advance
loop from Rust: open SQLite connections for prev/curr snapshots, read the diff using
Plan 13-01's `read_diff()`, then use Rayon `par_iter` to fan out changes across pipeline
operator chains. Each Rayon worker runs a pipeline's filter/join/take/exists operators
(reimplemented inline since cross-crate napi cdylib linking is not possible). Returns
aggregated `RowChange[]` as JSON to TS.

```rust
use std::collections::{HashMap, HashSet};
use std::sync::Arc;
use serde::{Serialize, Deserialize};
use rayon::prelude::*;

use crate::diff::{Change, Row, TableAndZqlSpec, DiffError};

#[derive(Debug, Clone, Deserialize)]
#[serde(tag = "type")]
pub enum Operator {
    #[serde(rename = "filter")]
    Filter { predicate: serde_json::Value },
    #[serde(rename = "join")]
    Join {
        parent_key: Vec<String>,
        child_key: Vec<String>,
        child_table: String,
        relationship: String,
    },
    #[serde(rename = "take")]
    Take {
        sort: Vec<(String, String)>,
        limit: Option<usize>,
    },
    #[serde(rename = "exists")]
    Exists {
        relationship: String,
        parent_field: Vec<String>,
        not_exists: bool,
    },
}

#[derive(Debug, Clone, Deserialize)]
pub struct PipelineConfig {
    pub query_id: String,
    pub source_tables: Vec<String>,
    pub operators: Vec<Operator>,
}

#[derive(Debug, Clone, Serialize)]
pub struct RowChange {
    #[serde(rename = "queryID")]
    pub query_id: String,
    pub table: String,
    pub row_key: serde_json::Value,
    pub row: Option<Row>,
    #[serde(rename = "type")]
    pub change_type: String,
}

#[derive(Debug, Serialize)]
pub struct AdvanceResult {
    pub changes: Vec<RowChange>,
    pub error: Option<String>,
    pub error_type: Option<String>,
}
```

<task id="13-02-03">
<title>Implement rust_advance napi function with Rayon par_iter</title>
<read_first>

<action>
Add to `packages/zqlite-rs/src/advance.rs` a `#[napi]` function `rust_advance`:

Signature:
```rust
#[napi]
pub fn rust_advance(
    db_path: String,
    prev_version: String,
    curr_version: String,
    syncable_tables_json: String,
    all_table_names_json: String,
    permissions_table: String,
    pipeline_configs_json: String,
) -> napi::Result<String>
```

Implementation:
1. Open two read-only SQLite connections with flags `SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_URI | SQLITE_OPEN_NO_MUTEX`
2. Execute `BEGIN DEFERRED` on each to acquire snapshot read locks (read-only connections use DEFERRED, not CONCURRENT which is for read-write)
3. Deserialize inputs from JSON: syncable_tables as `HashMap<String, TableAndZqlSpec>`, all_table_names as `HashSet<String>`, pipelines as `Vec<PipelineConfig>`
4. Call `crate::diff::read_diff()` on main thread -- handle DiffError::Reset/Truncate by returning AdvanceResult with error_type
5. Wrap changes in `Arc::new()`, use `pipelines.par_iter().map(|p| process_pipeline(p, &changes)).collect()` for Rayon fan-out
6. **Version check:** After `BEGIN DEFERRED`, read `_zero.replicationState` version from
      curr_conn. If it doesn't match the requested `curr_version`, ROLLBACK both connections
      and return an AdvanceResult with `error_type: "version_mismatch"`. This guards against
      the race where the replicator commits between TS `advanceWithoutDiff()` and Rust's BEGIN.
   7. Flatten results into AdvanceResult, ROLLBACK both connections, serialize to JSON string

Key design:
- Sync napi (not async) -- matches existing blocking advance pattern
- Opens own connections separate from TS Snapshotter (D-64/D-65)
- JSON serialization at boundary (D-55 pattern)
- Rayon degrades to serial for single pipeline
</action>
