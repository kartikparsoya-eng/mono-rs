Create `packages/zero-cache/src/services/dispatcher/rust-join.ts`:

```typescript
import type {Row} from '../../../zql/src/ivm/data.ts';
import type {CompoundKey} from '../../../zql/src/ivm/join-utils.ts';

// Conditional import — Rust bindings may not be available
let rustBindings: typeof import('zero-ivm-rs') | undefined;
try {
  rustBindings = require('zero-ivm-rs');
} catch {
  rustBindings = undefined;
}

/**
 * Returns true if Rust join acceleration is available.
 */
export function isRustJoinAvailable(): boolean {
  return rustBindings !== undefined
    && typeof rustBindings.rustJoinPushChildBatch === 'function';
}

/**
 * Rust-accelerated buildJoinConstraint.
 * Returns constraint object or undefined (matching TS signature).
 */
export function rustBuildJoinConstraint(
  sourceRow: Row,
  sourceKey: CompoundKey,
  targetKey: CompoundKey,
): Record<string, unknown> | undefined {
  if (!rustBindings) return undefined;
  const result = rustBindings.rustBuildJoinConstraint(
    JSON.stringify(sourceRow),
    sourceKey as string[],
    targetKey as string[],
  );
  if (result === null || result === undefined) return undefined;
  return JSON.parse(result);
}

/**
 * Rust-accelerated batch join for pushChildChange hot path.
 * Takes a child row, keys, and materialized parent rows from fetch().
 * Returns { constraint, matchResults } in a single napi call.
 */
export function rustJoinPushChildBatch(
  childRow: Row,
  childKey: CompoundKey,
  parentKey: CompoundKey,
  parentRows: Row[],
): {constraint: Record<string, unknown> | undefined; matchResults: boolean[]} {
  if (!rustBindings) {
    throw new Error('Rust join bindings not available');
  }
  const resultJson = rustBindings.rustJoinPushChildBatch(
    JSON.stringify(childRow),
    childKey as string[],
    parentKey as string[],
    parentRows.map(r => JSON.stringify(r)),
  );
  const parsed = JSON.parse(resultJson);
  return {
    constraint: parsed.constraint ?? undefined,
    matchResults: parsed.matchResults,
  };
}

/**
 * Rust-accelerated isJoinMatch (single-pair, for cases outside the batch path).
 */
export function rustIsJoinMatch(
  parentRow: Row,
  parentKey: CompoundKey,
  childRow: Row,
  childKey: CompoundKey,
): boolean {
  if (!rustBindings) return false;
  return rustBindings.rustIsJoinMatch(
    JSON.stringify(parentRow),
    parentKey as string[],
    JSON.stringify(childRow),
    childKey as string[],
  );
}

/**
 * Rust-accelerated rowEqualsForCompoundKey.
 */
export function rustRowEqualsForCompoundKey(
  a: Row,
  b: Row,
  key: CompoundKey,
): boolean {
  if (!rustBindings) return false;
  return rustBindings.rustRowEqualsForCompoundKey(
    JSON.stringify(a),
    JSON.stringify(b),
    key as string[],
  );
}
```

## Task 2: Wire Rust join into pipeline-driver delegate

<read_first>
- packages/zero-cache/src/services/dispatcher/pipeline-driver.ts (existing delegate, createStorage pattern, how operators are constructed)
- packages/zql/src/ivm/join.ts (Join constructor, how it uses join-utils functions)
- packages/zql/src/ivm/graph/graph.ts (how operators are wired into the pipeline graph)
</read_first>

<action>
Modify `packages/zero-cache/src/services/dispatcher/pipeline-driver.ts` to integrate Rust join acceleration:

The key challenge: Join's hot-path functions (isJoinMatch, buildJoinConstraint) are called from *private methods* inside the Join class (`#pushChildChange`, `#processParentNode`). We cannot modify join.ts (D-44). Two integration strategies:

**Strategy A — Module-level function override (preferred):**

The Join class imports `isJoinMatch`, `buildJoinConstraint`, `rowEqualsForCompoundKey` from `join-utils.ts`. If join-utils.ts exports them as mutable bindings, we could override them at the module level. However, since we can't modify packages/zql/ files, this won't work directly.

**Strategy B — Pipeline delegate with materialized batch interception:**

Add a `joinDelegate` to the existing pipeline delegate interface:

```typescript
interface PipelineDelegate {
  // existing
  createStorage<V>(name: string): Storage<V>;

  // new: join acceleration
  joinPushChildBatch?: (
    childRow: Row,
    childKey: CompoundKey,
    parentKey: CompoundKey,
    parentRows: Row[],
  ) => {constraint: Record<string, unknown> | undefined; matchResults: boolean[]};
}
```

Then create a wrapper that sits between the Join operator and its child input. The wrapper intercepts `push()` calls, materializes the parent fetch results, calls `rustJoinPushChildBatch`, and replays only the matching parents — avoiding the per-row isJoinMatch calls in TS.

**Concrete implementation:**

1. In pipeline-driver.ts, when constructing Join operators, check `isRustJoinAvailable()`.
2. If available, wrap the Join's push path with a `RustAcceleratedJoinPush` that:
   - Intercepts child changes before they reach Join's `#pushChildChange`
   - Materializes parent.fetch() results into an array
   - Calls `rustJoinPushChildBatch()` once
   - Filters parent rows by matchResults
   - Calls the original push with pre-filtered parents (or uses a custom code path)

**Alternative cleaner approach:**

Since Join imports `{isJoinMatch, buildJoinConstraint, rowEqualsForCompoundKey}` from `'./join-utils.ts'`, and the pipeline-driver controls operator instantiation, we can:

1. Create a patched join-utils module that delegates to Rust when available
2. Use Node.js module resolution to inject it

However, this is fragile. The **recommended approach** for Phase 11 is:

**Create a RustJoinInput class** in zero-cache that wraps a standard Join but overrides the input pipeline. The RustJoinInput:
- Accepts the same constructor args as Join
- Creates an internal Join instance
- Monkey-patches the internal Join's `push` method to intercept child changes
- Before the child change reaches `#pushChildChange`, materializes parents and calls Rust batch
- Passes only matching parents through to minimize TS-side work

Add to pipeline-driver.ts:

```typescript
import {isRustJoinAvailable, rustJoinPushChildBatch} from './rust-join.ts';

// In the operator construction section where Join operators are created:
if (isRustJoinAvailable()) {
  // Log that Rust join acceleration is active
  delegate.joinPushChildBatch = rustJoinPushChildBatch;
}
```

The exact wiring depends on how pipeline-driver.ts currently constructs Join operators. Read the file carefully and integrate at the point where Join instances are created, adding the Rust delegate when available.
</action>
