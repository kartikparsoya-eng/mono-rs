# Plan 12-02: TS Integration + Delegate Wiring

<objective>
Create a TS wrapper (`rust-exists.ts`) that intercepts Exists operator push()
calls, pre-resolves fetchSize for CHILD changes that need it, calls the Rust
batch function, and applies the returned actions. Wire into pipeline-driver
via the `decorateFilterInput` delegate method. All existing tests must pass
unchanged.
</objective>

<tasks>

<task id="01">
<title>Create rust-exists.ts wrapper module</title>
<read_first>
- packages/zql/src/ivm/exists.ts (full Exists class — understand filter/push/fetchSize)
- packages/zero-cache/src/services/view-syncer/rust-join.ts (pattern for conditional import + wrapper)
- packages/zql/src/ivm/filter-operators.ts (FilterOperator, FilterInput, FilterOutput interfaces)
- packages/zql/src/ivm/change.ts (Change tuple structure, makeAddChange, makeRemoveChange)
- packages/zql/src/ivm/change-index.ts (ChangeIndex enum)
- packages/zql/src/ivm/change-type.ts (ChangeType enum)
</read_first>
<action>
Create `packages/zero-cache/src/services/view-syncer/rust-exists.ts`:

1. Conditional import of `rustExistsPushBatch` from `zero-ivm-rs` (same pattern as rust-join.ts)

2. Export `isRustExistsAvailable(): boolean`

3. Export `createRustExistsWrapper(original: FilterOperator, relationshipName: string, parentJoinKey: CompoundKey, existsType: 'EXISTS' | 'NOT EXISTS'): FilterOperator`

   Returns a wrapper object implementing FilterOperator that:
   - `setFilterOutput(output)`: delegates to original
   - `beginFilter()`: delegates to original
   - `endFilter()`: delegates to original
   - `filter(node)`: delegates to original (generator, cache logic stays in TS)
   - `destroy()`: delegates to original
   - `getSchema()`: delegates to original
   - `push(change)`: **INTERCEPTED** — the hot path:
     a. For each change in the push, classify it:
     - ADD/EDIT/REMOVE: no fetchSize needed
     - CHILD with matching relationship + add/remove childChangeType:
       call original's private fetchSize via the relationship generator on the node
       b. Build JSON array of change descriptors with pre-resolved fetchedSize
       c. Call `rustExistsPushBatch(changesJson, relationshipName, notExists)`
       d. Parse returned actions array
       e. For each action:
     - "pass_filter": call original pushWithFilter logic (filter then output.push)
     - "pass_filter_with_exists": call filter with pre-resolved exists, then output.push
     - "convert_add": call output.push(makeAddChange(node))
     - "convert_remove": call output.push(makeRemoveChange(node)) with appropriate relationships

   CRITICAL: The wrapper must handle the `#inPush` flag and generator yields correctly.
   Since Exists.push() is a generator, the wrapper must also be a generator.

4. IMPORTANT: The wrapper does NOT replace the Exists class — it wraps it.
   The Exists instance is constructed normally by the builder. The wrapper
   intercepts push() to use Rust for decision logic, but delegates filter()
   and lifecycle methods to the original Exists instance.
   </action>
   <acceptance_criteria>

- `packages/zero-cache/src/services/view-syncer/rust-exists.ts` exists
- Exports `isRustExistsAvailable` and `createRustExistsWrapper`
- Wrapper implements full FilterOperator interface
- push() calls `rustExistsPushBatch` for batch decision logic
- filter(), beginFilter(), endFilter() delegate to original Exists
- No modifications to `packages/zql/` files
  </acceptance_criteria>
  </task>

1. Add import: `import { isRustExistsAvailable, createRustExistsWrapper } from './rust-exists.ts';`

2. Add constant: `const USE_RUST_EXISTS = USE_RUST_IVM && isRustExistsAvailable();`

3. In the `buildPipeline` delegate's `decorateFilterInput` method:
   - Check if the input is an Exists operator (by checking the `name` parameter which
     contains "exists" — e.g. `queryID:exists(comments)`)
   - If USE_RUST_EXISTS and name contains `:exists(`:
     - Extract relationship name and other params from the Exists instance
     - Return `createRustExistsWrapper(input, ...)` instead of bare input
   - Otherwise: return input unchanged (current behavior)

4. Log when Rust exists acceleration is active (same pattern as join logging).
