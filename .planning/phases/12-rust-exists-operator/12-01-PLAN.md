# Plan 12-01: Rust Exists Batch Push Function

<objective>
Implement a Rust napi function `rust_exists_push_batch` that encodes the Exists
operator's push-path decision logic. Given a batch of serialized changes with
pre-resolved exists/size values from TS, it returns an array of output actions
(emit, skip, convert-to-add, convert-to-remove) so that the TS wrapper can
produce the correct output changes without per-change JS logic.
</objective>

<tasks>

<task id="01">
<title>Create exists.rs module with ExistsAction enum and batch function</title>
<read_first>
- packages/zql/src/ivm/exists.ts (push method logic, lines 109-208)
- packages/zero-ivm-rs/src/join.rs (pattern for napi JSON functions)
- packages/zero-ivm-rs/src/filter.rs (Value enum, parse helpers)
</read_first>
<action>
Create `packages/zero-ivm-rs/src/exists.rs`:

1. Define input/output types for the batch function:
   - Input: JSON array of change descriptors, each with:
     - `type`: "add" | "remove" | "edit" | "child"
     - `childRelationship`: string | null (for child changes)
     - `childChangeType`: "add" | "remove" | "edit" | "child" | null
     - `fetchedSize`: number | null (pre-resolved by TS for child add/remove on matching relationship)
   - Config: `relationshipName` (string), `not` (bool)
   - Output: JSON array of action descriptors:
     - `action`: "pass_filter" | "skip" | "convert_add" | "convert_remove" | "pass_filter_with_exists"
     - `exists`: bool | null (pre-computed exists value to pass to pushWithFilter)

2. Implement `decide_exists_push` internal function that encodes the decision tree from exists.ts push():
   - ADD/EDIT/REMOVE → `pass_filter` (exists=null, let filter() resolve)
   - CHILD where childRelationship != relationshipName → `pass_filter`
   - CHILD where childChangeType is "edit" or "child" → `pass_filter`
   - CHILD ADD where fetchedSize == 1:
     - if not: `convert_remove` (relationship becomes empty)
     - else: `convert_add`
   - CHILD ADD where fetchedSize != 1:
     - `pass_filter_with_exists` with exists = (fetchedSize > 0)
   - CHILD REMOVE where fetchedSize == 0:
     - if not: `convert_add`
     - else: `convert_remove` (need to include removed child in relationships)
   - CHILD REMOVE where fetchedSize != 0:
     - `pass_filter_with_exists` with exists = (fetchedSize > 0)

3. Implement `#[napi] pub fn rust_exists_push_batch(changes_json: String, relationship_name: String, not_exists: bool) -> String`
   - Parses input JSON array
   - Calls decide_exists_push for each change
   - Returns JSON array of actions

4. Add comprehensive unit tests:
   - test_add_pass_filter: ADD → pass_filter
   - test_edit_pass_filter: EDIT → pass_filter
   - test_remove_pass_filter: REMOVE → pass_filter
   - test_child_different_relationship: CHILD with wrong rel → pass_filter
   - test_child_edit_pass_filter: CHILD EDIT → pass_filter
   - test_child_child_pass_filter: CHILD CHILD → pass_filter
   - test_child_add_size_1_exists: CHILD ADD, size=1, EXISTS → convert_add
   - test_child_add_size_1_not_exists: CHILD ADD, size=1, NOT EXISTS → convert_remove
   - test_child_add_size_gt_1: CHILD ADD, size=3 → pass_filter_with_exists(true)
   - test_child_add_size_0: CHILD ADD, size=0 → pass_filter_with_exists(false) — edge case, shouldn't happen but handle gracefully
   - test_child_remove_size_0_exists: CHILD REMOVE, size=0, EXISTS → convert_remove
   - test_child_remove_size_0_not_exists: CHILD REMOVE, size=0, NOT EXISTS → convert_add
   - test_child_remove_size_gt_0: CHILD REMOVE, size=2 → pass_filter_with_exists(true)
   - test_napi_batch_multiple: batch of 3 mixed changes, verify all actions
   - test_napi_batch_empty: empty batch → empty array
     </action>
