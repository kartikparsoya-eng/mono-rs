### Task 2 — fast-check arbitraries (arb-ast.ts)

- **type:** auto
- **behavior:** Per-operator fast-check arbitraries composed via `fc.letrec` for
  recursion. Schema-driven: re-uses `schema as paritySchema` from `zero-schema.ts`
  (same pattern as `ast-fuzz.ts` lines 1-50). Exports `buildArbitraries(schema)`
  returning `{ arbAst: fc.Arbitrary<AST> }`. Scaffolding only — produces simple
  ASTs covering Filter, EXISTS, And/Or, Take, Skip. Targeted shapes for B1/B2/B3
  documented in TODO comments for Wave 1 expansion.
- **file:** `tools/ivm-parity/arb-ast.ts` (NEW)
- **citation:** RESEARCH "fast-check Generator Design (CD-01)" + RESEARCH "Code
  Examples — Example 3"; D-04 (BFS preserved alongside).
- **verify:** `npx tsx tools/ivm-parity/arb-ast.ts` exits 0 (smoke import);
  `node -e "const fc = require('fast-check'); console.log(fc.constantFrom)"` works.

### Task 3 — Shared roundtrip primitive (harness-fuzz.ts)

- **type:** auto
- **behavior:** Extract a thin reusable primitive `runOneAst(ast, schema, urls)`
  that wraps the WebSocket subscribe → hydrate → snapshot flow already present
  in `harness-coverage.ts`. Return a `{ tsRows, rsRows, divergence?: Diff }`.
  No new harness logic — the fast-check driver uses this primitive per iteration.
  Scaffolding stub returns hard-coded shape; Wave 1 task wires the actual
  `subscribeAndHydrate`.
- **file:** `tools/ivm-parity/harness-fuzz.ts` (NEW)
- **citation:** RESEARCH "Two-Process Harness Reuse — Reusable primitives";
  CONTEXT C-2 reusable primitives.
- **verify:** `npx tsx tools/ivm-parity/harness-fuzz.ts --smoke` exits 0.

### Task 4 — fast-check driver script (random-ast-fuzz.ts)

- **type:** auto
- **behavior:** fast-check entry point. Reads `FUZZ_NUM_RUNS` (default 100 in
  Wave 0; Wave 1 raises to 1000), `FUZZ_SEED`, builds arbitraries via Task 2's
  `buildArbitraries`, runs `fc.assert(fc.asyncProperty(arb.ast, ...))`, calls
  Task 3's `runOneAst`, applies Task 1's allow-list to filter expected
  divergences, exits 0 iff zero unexpected divergences. Scaffolding does NOT
  yet do batching (Wave 1 adds `BatchedRunner`).
- **file:** `tools/ivm-parity/random-ast-fuzz.ts` (NEW)
- **citation:** RESEARCH "Pattern 2: Hot-fixture iteration loop";
  CONTEXT D-05/D-06.
- **verify:** `cd tools/ivm-parity && FUZZ_NUM_RUNS=5 npx tsx random-ast-fuzz.ts --dry-run`
  exits 0 (dry-run: skips network, just verifies arbitrary draws).
