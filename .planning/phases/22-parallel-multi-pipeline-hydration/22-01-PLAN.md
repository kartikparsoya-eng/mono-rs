# Plan 22-01: LiveTableSource Operator & Parallel Hydration Engine

<objective>
Create a LiveTableSource operator that bridges RustTableSource into the Operator trait, then build a parallel hydration engine that constructs N pipelines from configs and runs them concurrently via Rayon, each with its own pooled SQLite connection.
</objective>

<must_haves>

- LiveTableSource: implements Operator trait, holds Arc<RustTableSource>, delegates fetch() to table_source.fetch()
- hydrate_pipelines(): accepts Vec<PipelineConfig> (table_name + operator config JSON), builds operator trees, fetches in parallel via rayon::par_iter
- Each pipeline gets its own connection from the pool (pool sized to thread count)
- Results returned as Vec<(pipeline_id, Vec<Node>)> — ordered by pipeline_id
- All pipelines see same WAL snapshot (connection pool guarantee)
- Error handling: if any pipeline fails, collect errors without poisoning others
  </must_haves>

<threat_model>

- Thread safety: RustTableSource behind Arc, fetch() takes &self — safe for concurrent reads
- Pool exhaustion: if more pipelines than pool connections, some threads block. Size pool to rayon thread count.
- Panic safety: rayon catch_unwind per pipeline to avoid poisoning thread pool
- Memory: each pipeline's Vec<Node> held in memory until returned. For very large result sets, this could spike RSS. Acceptable for v4.0; streaming can be added later.
  </threat_model>
