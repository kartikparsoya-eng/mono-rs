<objective>
Fix AUDIT-04 (Risk #3 from `.planning/IVM-PORT-AUDIT.md`): `ExistsOperator::push_impl::Edit` and the equivalent in `OrExistsOperator` only evaluate `or_predicate` on the new row. When a parent edit flips the or-condition truth value (e.g. old row matched via or_predicate, new row doesn't AND has no children), the operator silently keeps the stale row in the output.

Purpose: With AUDIT-02 (Plan 02) ensuring parent_field never changes inside an Edit, the only way an Exists membership can flip on Edit is via the or_predicate flipping. This fix evaluates the predicate on both rows and emits Add/Remove/Edit/nothing per the 4-transition truth table. Without this fix, OR(simple, EXISTS) patterns produce wrong output on edits that flip the simple side.

Output: Updated Edit branch in both `ExistsOperator::push_impl` and `OrExistsOperator::push_impl`, plus 4 unit tests per operator covering all 4 transitions.

**Why this depends on Plan 02:** The fix in this plan assumes the EXISTS parent_field doesn't change between old_node.row and node.row in an Edit (so `parent_sizes` lookup works for both). Plan 02 (AUDIT-02) enforces that invariant by ensuring parent_field column edits are split into Remove+Add at the source — never reaching the operator as an Edit. If Plan 02 is not yet shipped, the cached `parent_sizes` could disagree between old/new pks, leading to wrong counts. With Plan 02 in place, old_pk == new_pk inside any Edit reaching this code path, and the cached count is correct for both sides.
</objective>

<truth-table>
The 4-transition matrix per D-12. Inputs: `old_passed`, `new_passed` ∈ {true, false}.

| old_passed | new_passed | Emit                                                       |
| ---------- | ---------- | ---------------------------------------------------------- |
| true       | true       | `Edit { node, old_node }` (pass-through, current behavior) |
| true       | false      | `Remove(old_node)`                                         |
| false      | true       | `Add(node)`                                                |
| false      | false      | nothing (`vec![]`)                                         |

For ExistsOperator: `passed = or_condition_matches(row) || passes_filter(count)`.
For OrExistsOperator: `passed = or_condition_matches(row) || any_branch_passes(row)` (i.e. `row_passes(row)`).

Per D-13: use the cached `parent_sizes` for both old and new. With AUDIT-02 enforced upstream (Plan 02), old_pk == new_pk inside any Edit so the same cache entry serves both. If old_pk != new_pk slips through, fall back to `fetch_child_count(&old_row)` for the old side.
