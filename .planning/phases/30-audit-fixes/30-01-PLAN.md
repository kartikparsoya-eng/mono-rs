<objective>
Fix AUDIT-01 (Bug #1 from `.planning/IVM-PORT-AUDIT.md`): `parse_predicate_json` in hydrate.rs constructs `Predicate::Like(_, _, true)` for the `like` key, making LIKE silently case-insensitive. Change the third argument to `false` and add a regression test that distinguishes LIKE from ILIKE matching behavior.

Purpose: Without this fix, every Rust-evaluated `LIKE 'Foo%'` matches `'foo bar'`, `'FOO'`, etc., producing wrong query results in production. The other parser (`pipeline.rs::parse_predicate` at lines 128-135) is already correct and serves as the parity reference.

Output: One-character fix (`true` → `false`) on line 769 of hydrate.rs, plus a `#[cfg(test)] mod tests` block extension that proves LIKE is case-sensitive and ILIKE is case-insensitive.

```rust
pub enum Predicate {
    Eq(String, Value),
    Neq(String, Value),
    Gt(String, Value), Lt(String, Value), Gte(String, Value), Lte(String, Value),
    In(String, Vec<Value>),
    Like(String, String, bool), // (field, pattern, case_insensitive)
    IsNull(String), IsNotNull(String),
    And(Vec<Predicate>), Or(Vec<Predicate>), Not(Box<Predicate>),
}

pub fn evaluate_json_row(pred: &Predicate, row: &Row) -> bool;
```

The third argument of `Predicate::Like` is `case_insensitive`. `like_match_impl` in filter.rs uses `to_ascii_lowercase()` when this is `true` — so the Rust evaluator does honor the flag. The bug is purely in how `parse_predicate_json` constructs the predicate.

Correct counterpart in `packages/zero-ivm-rs/src/pipeline.rs` lines 128-135:

```rust
if let Some(val) = obj.get("like") {
    let pattern = val.as_str().ok_or("'like' value must be a string")?.to_string();
    return Ok(Predicate::Like(field, pattern, false));   // ← false
}
if let Some(val) = obj.get("ilike") {
    let pattern = val.as_str().ok_or("'ilike' value must be a string")?.to_string();
    return Ok(Predicate::Like(field, pattern, true));    // ← true
}
```
