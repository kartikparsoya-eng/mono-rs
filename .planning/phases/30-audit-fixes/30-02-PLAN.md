<objective>
Fix AUDIT-02 (Bug #2 from `.planning/IVM-PORT-AUDIT.md`): `collect_split_edit_keys` in advance.rs misses the `Condition::CorrelatedSubquery` arm in `collect_from_cond`. This means when an EXISTS lives in a where clause, its `parent_field` columns are not added to split_edit_keys, so editing such a column produces an `Edit` (instead of `Remove + Add`). The downstream `ExistsOperator::push_impl::Edit` then only consults the new row's child count, silently dropping the membership transition.

Purpose: Without this fix, edits that flip an EXISTS condition's truth value silently produce wrong output (stale rows remain, new memberships emit `Edit` instead of `Add`). This is the worst class of regression — silent and edit-pattern-specific. The TS parity reference is `packages/zql/src/builder/builder.ts` lines 273-290, which gathers splitEditKeys from BOTH `ast.related[*].correlation.parentField` AND `gatherCorrelatedSubqueryQueryConditions(ast.where)[*].related.correlation.parentField`.

Output: Add a `Condition::CorrelatedSubquery` arm to the inner `collect_from_cond` function. Add unit + integration tests covering both directions of the membership flip.
</objective>

fn collect_split_edit_keys(ast: &crate::ast_to_config::Ast) -> Vec<String> {
    let mut keys = std::collections::HashSet::new();
    if let Some(related) = &ast.related {
        for rel in related {
            for field in &rel.correlation.parent_field {
                keys.insert(field.clone());
            }
        }
    }
    fn collect_from_cond(cond: &crate::ast_to_config::Condition, keys: &mut std::collections::HashSet<String>) {
        match cond {
            crate::ast_to_config::Condition::And { conditions } |
            crate::ast_to_config::Condition::Or { conditions } => {
                for c in conditions {
                    collect_from_cond(c, keys);
                }
            }
            _ => {}    // ← BUG: misses Condition::CorrelatedSubquery
        }
    }
    if let Some(cond) = &ast.where_cond {
        collect_from_cond(cond, &mut keys);
    }
    keys.into_iter().collect()
}

const csqConditions = gatherCorrelatedSubqueryQueryConditions(ast.where);

  : new Set();

  for (const key of csq.related.correlation.parentField) {
    splitEditKeys.add(key);

      splitEditKeys.add(key);
    }
  }
}
