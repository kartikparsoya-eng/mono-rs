# Vitest Pipeline Mutation Tests

<objective>
Create `pipeline-driver.concurrency.test.ts` with integration tests proving that adding, removing, and churning pipelines between consecutive `rust_advance()` calls does not corrupt state (CON-02).
</objective>

<must_haves>

- Test: add pipeline between advance calls — new pipeline produces correct results

- Test: rapid churn (remove 5, add 5 of 10) — only surviving+new pipelines produce output
- All queries are filter-only (Rust-eligible) to exercise the Rust path

**Test 1: "add pipeline between advance calls gets correct results"**

1. `pipelines.init(numberClientSchema)`
2. `[...pipelines.addQuery('h1', 'q1', ALL_ITEMS, startTimer())]`
3. `replicator.processTransaction('134', messages.insert('number_items', {id: 'n6', val: 60, label: 'f'}))`
4. `const r1 = changes()` — expect q1 results present
5. `[...pipelines.addQuery('h2', 'q2', VAL_GT_20, startTimer())]` — hydration for q2
6. `replicator.processTransaction('135', messages.insert('number_items', {id: 'n7', val: 70, label: 'g'}))`
7. `const r2 = changes()` — expect both q1 and q2 results, q2 should include n7 (val 70 > 20)
8. `expect(r2.some(c => c.queryID === 'q1')).toBe(true)`
9. `expect(r2.some(c => c.queryID === 'q2')).toBe(true)`

**Test 2: "remove pipeline between advance calls — no stale output"**

1. Init, addQuery q1 (ALL_ITEMS) + q2 (VAL_GT_20)
2. Process insert n6, advance — both q1 and q2 produce results
3. `pipelines.removeQuery('q1')`
4. Process insert n7, advance
5. `expect(result.every(c => c.queryID === 'q2')).toBe(true)` — no q1 results

**Test 3: "add and remove in same interval"**

1. Init, addQuery q1 (ALL_ITEMS), q2 (VAL_GT_20), q3 (VAL_LT_40)
2. Process insert, advance — all 3 produce results
3. `pipelines.removeQuery('q1')`, `[...pipelines.addQuery('h4', 'q4', LABEL_EQ_A, startTimer())]`
4. Process insert, advance
5. Assert: no q1 in results, q2/q3/q4 present (q4 may be empty if inserted row label != 'a', that's ok — just no q1)
6. `expect(result.every(c => c.queryID !== 'q1')).toBe(true)`

**Test 4: "remove all pipelines — empty results, no errors"**

1. Init, addQuery q1
2. Process insert, advance — results present
3. `pipelines.removeQuery('q1')`
4. `expect(pipelines.queries().size).toBe(0)`
5. Process insert, advance
6. `expect(result).toHaveLength(0)`

**Test 5: "rapid pipeline churn — remove 5 add 5"**

1. Init, add 10 queries: q0-q9 with varied filters (use ALL_ITEMS, VAL_GT_20, VAL_LT_40, LABEL_EQ_A, LABEL_EQ_B, VAL_GT_0 and repeat with different hashes)
2. Process insert, advance — results from multiple queries
3. Remove q0-q4, add q10-q14 (5 new queries with remaining filters)
4. Process insert, advance
5. Assert: no q0-q4 in results, q5-q9 and q10-q14 may appear
6. `const removedIds = new Set(['q0','q1','q2','q3','q4'])`
7. `expect(result.every(c => !removedIds.has(c.queryID))).toBe(true)`
