# Plan 03: Separate IVM Crate + Delegate-Based Integration

<objective>
Create a dedicated `zero-ivm-rs` napi crate for IVM operators (moved out of `zqlite-rs`).
Integrate Rust Take storage via the existing `BuilderDelegate.createStorage()` hook
in `pipeline-driver.ts`. Zero modifications to any file in `packages/zql/`.
Filter integration deferred to plan 10-04 (requires `BuilderDelegate` interface extension).
</objective>

<architecture>
## Why a separate crate

- `zqlite-rs` is the SQLite binding layer — IVM logic doesn't belong there.
- Separate build means IVM Rust tests run fast without compiling SQLite.
- Any package (zqlite, zero-cache) can depend on `zero-ivm-rs` independently.

## Integration via delegate pattern (no zql changes)

The pipeline builder calls `delegate.createStorage(name)` for every Take operator.
In production, `pipeline-driver.ts` provides the delegate. We change its
`createStorage()` to return `RustTakeStorage` (Rust HashMap) instead of
`DatabaseStorage` (SQLite). This is a targeted change at the call site.

For Filter: `builder.ts` creates `new Filter(input, predicate)` directly —
there's no delegate hook. `decorateFilterInput` return value is unused (line 592).
A clean Filter integration requires adding an optional `createFilter?` method
to `BuilderDelegate`. This is a separate plan (10-04) since it touches the
`zql` interface definition.

## Fallback

`ZERO_DISABLE_RUST_IVM=1` env var → `createStorage()` returns DatabaseStorage
as before. Default: Rust path enabled.
</architecture>

## Task 2: Create RustTakeStorage TS adapter in new package

<read_first>

- packages/zql/src/ivm/operator.ts (Storage interface)
- packages/zql/src/ivm/take.ts (how Storage is used by Take)
- packages/zqlite/src/database-storage.ts (current Storage impl)
  </read_first>

<action>
Create `packages/zero-ivm-rs/ts/rust-take-storage.ts`:

Implements `Storage` interface from `zql/src/ivm/operator.ts`.
Wraps `RustTakeState` from the co-located napi module.
Methods: get (HashMap lookup + JSON.parse), set (JSON.stringify + HashMap insert), del, scan (throws — Take never calls it).

Take only uses get/set/del. The perf win: Rust HashMap vs SQLite SELECT/INSERT + JSON round-trip per access.
</action>
