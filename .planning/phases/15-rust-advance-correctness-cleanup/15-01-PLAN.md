## Task 1: Fix edit semantics in advance.rs

<read_first>
- packages/zqlite-rs/src/advance.rs (current process_change_for_pipeline implementation around line 280)
- packages/zero-cache/src/services/view-syncer/pipeline-driver.ts (TS advance path edit handling for reference)
</read_first>

<action>
In `process_change_for_pipeline()` in advance.rs, replace the positional `prev_values[0]` indexing with primary key matching logic:

1. Extract the pipeline's primary key columns from PipelineConfig (add a `primary_key: Vec<String>` field to PipelineConfig struct if not present)
2. When processing an edit (prev_values.len() > 0 && next_values.len() > 0):
   - Find the prev_value whose PK columns match the next_value's PK columns using value equality
   - If no match found, treat as separate add + remove operations
   - If match found, emit edit with that matched prev row
3. Add unit tests for:
   - Edit with single prev_value (existing behavior preserved)
   - Edit with multiple prev_values where PK identifies correct match
   - Edit with no PK match falling back to add+remove
</action>

<acceptance_criteria>

- `cargo test` in packages/zqlite-rs passes with 0 failures
- New test `test_edit_matches_by_primary_key` exists and passes
- New test `test_edit_no_pk_match_becomes_add_remove` exists and passes
</acceptance_criteria>
