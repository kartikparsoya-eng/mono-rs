# Plan 27-01: Rust `rust_dispatch_poke` NAPI Function

<objective>
Add a new `rust_dispatch_poke` napi function that accepts pipeline configs from multiple ViewSyncers, runs Rayon fan-out for all of them in parallel, and returns per-VS results in binary buffer format.
</objective>

<task id="01">
<title>Add rust_dispatch_poke napi function</title>
<read_first>
- packages/zqlite-rs/src/advance.rs (existing rust_fan_out and rust_advance_full functions)
- packages/zqlite-rs/index.d.ts (existing type declarations)
</read_first>
<action>
In `packages/zqlite-rs/src/advance.rs`, add a new `#[napi]` function `rust_dispatch_poke` that:

1. Accepts `changes_json: String` (same format as rust_fan_out) and `vs_pipelines_json: String` (JSON array of `{vs_id: string, pipelines: PipelineConfig[]}`)
2. Returns `Buffer` (binary result)
3. Deserializes inputs, then uses `rayon::par_iter()` over VS entries
4. For each VS, evaluates all its pipelines against the changes using existing `evaluate_pipeline_changes` logic
5. Wraps per-VS results with error isolation via `std::panic::catch_unwind`
6. Serializes to buffer: `[u32 vs_count]` then per VS: `[u32 vs_id_len][vs_id bytes][u32 change_count][changes...]` or error sentinel `[u32 vs_id_len][vs_id bytes][0xFFFFFFFF][u32 err_len][err bytes]`

Also add the TS type declaration in `packages/zqlite-rs/index.d.ts`:

```typescript
export declare function rustDispatchPoke(
  changesJson: string,
  vsPipelinesJson: string,
): Buffer;
```

</action>
<acceptance_criteria>
- `packages/zqlite-rs/src/advance.rs` contains `pub fn rust_dispatch_poke(`
- Function has `#[napi]` attribute and returns `Buffer`
- Function uses `rayon::par_iter()` for VS-level parallelism
- Function uses `std::panic::catch_unwind` for per-VS error isolation
- `packages/zqlite-rs/index.d.ts` contains `export declare function rustDispatchPoke(`
- `cargo build` in `packages/zqlite-rs/` succeeds
</acceptance_criteria>
</task>
