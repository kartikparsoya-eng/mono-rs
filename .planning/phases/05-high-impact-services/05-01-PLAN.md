4. Serialize to binary buffer using allBuf protocol:

This mirrors Statement.allBuf() but is a one-shot method (no prepared statement management needed).
Note: safeIntegers behavior is handled by TS decodeBuf (BigInt for values outside safe range).

```typescript
/**
 * Get a single row with typed conversion done in Rust.
 * Returns undefined if no row matches.
 */
getRow<T>(
  sql: string,
  params: unknown[],
  columnTypes: Record<string, string>,
  tableName: string,
): T | undefined {
  return this.#run('getRow', sql, () =>
    this.#db.getRow(sql, params, columnTypes, tableName),
  );
}

/**
 * Get multiple rows as a binary buffer (allBuf protocol).
 * Decode with decodeBuf(). For hot paths with potentially many rows.
 */
getRowsBuf(sql: string, params: unknown[]): Buffer {
  return this.#run('getRowsBuf', sql, () =>
    this.#db.getRowsBuf(sql, params),
  );
}

/**
 * Get a batch of change log entries as a binary buffer.
 * Returns allBuf buffer with 4 text columns: stateVersion, table, rowKey, op.
 * Call repeatedly with increasing offset until row_count < batchSize.
 */
changesSinceBuf(prevVersion: string, batchSize: number, offset: number): Buffer {
  return this.#run('changesSinceBuf', `changeLog2 > ${prevVersion}`, () =>
    this.#db.changesSinceBuf(prevVersion, batchSize, offset),
  );
}
```
</action>

```typescript
changesSince(prevVersion: string) {
  const batchSize = 500;
  let offset = 0;
  let done = false;
  const colNames = ['stateVersion', 'table', 'rowKey', 'op'];
  const db = this.db.db;

  const iterator: IterableIterator<any> = {
    [Symbol.iterator]() { return this; },
    next() {
      // This is a simplified approach — we buffer one batch at a time
      // The actual implementation uses a generator pattern
    },
    return() { return { value: undefined, done: true }; }
  };
  // Actually, use a generator:
  function* generate() {
    let offset = 0;
    for (;;) {
      const buf = db.changesSinceBuf(prevVersion, batchSize, offset);
      const rows = decodeBuf(buf, colNames);
      for (const row of rows) yield row;
      if (rows.length < batchSize) return;
      offset += batchSize;
    }
  }
  const gen = generate();
  return { changes: gen, cleanup: () => { gen.return(undefined); } };
}
```

5. **Remove** `safeIntegers(true)` calls (Rust handles this internally via the allBuf protocol / getRow typed conversion).

**CRITICAL:** The `fromSQLiteTypes` call in Diff[Symbol.iterator] (lines 532-536) must still be called for getRows results since allBuf doesn't do type conversion. For getRow, Rust does type conversion inline — BUT we need to pass the zqlSpec types, not the dataType. 

**Resolution:** Actually, looking more carefully:
- `getRow` in Rust uses `columnTypes` which maps to queryAll's pattern (boolean/json conversion)
- The Diff iterator calls `fromSQLiteTypes(zqlSpec, row, table)` on the result
- If Rust already converted booleans/json, calling fromSQLiteTypes again would double-convert

**Fix:** For getRow, pass columnTypes derived from `zqlSpec` (the ZQL schema types), so Rust does the conversion and the Diff iterator can skip `fromSQLiteTypes` for getRow results. For getRows (allBuf path), TS still calls fromSQLiteTypes after decode.

OR simpler: Don't pass columnTypes to getRow — use empty `{}` — and let fromSQLiteTypes handle conversion in TS as before. This is simpler and avoids any risk of double-conversion.

**CHOSEN APPROACH:** Pass empty columnTypes `{}` to Rust getRow (no type conversion in Rust), keep fromSQLiteTypes in the Diff iterator unchanged. The perf gain comes from avoiding statement cache overhead and napi per-call costs, not from type conversion.
