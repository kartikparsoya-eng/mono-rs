# Plan 01: Fix NOT EXISTS Wiring + Integration Tests

## Goal

Fix the hardcoded `'EXISTS'` at pipeline-driver.ts:507 so that NOT EXISTS queries pass the correct `existsType` to `createRustExistsWrapper`, then add integration tests proving the fix works end-to-end.

## Background

The `decorateFilterInput` callback in `pipeline-driver.ts` always passes `'EXISTS'` to `createRustExistsWrapper` (line 507). The `Exists` class stores the type in a private field `#not` which is inaccessible from outside. The solution is to extract EXISTS/NOT EXISTS type from the AST's `where` conditions before building the pipeline, then look up the relationship name in `decorateFilterInput`.

In `pipeline-driver.ts`, add a helper function that walks an AST's `where` conditions to extract a `Map<string, 'EXISTS' | 'NOT EXISTS'>` keyed by relationship alias:

```typescript
function collectExistsTypes(
  condition: Condition | undefined,
  map: Map<string, 'EXISTS' | 'NOT EXISTS'> = new Map(),
): Map<string, 'EXISTS' | 'NOT EXISTS'> {
  if (!condition) return map;
  switch (condition.type) {
    case 'correlatedSubquery':
      map.set(condition.related.subquery.alias, condition.op);
      collectExistsTypes(condition.related.subquery.where, map);
      break;
    case 'and':
    case 'or':
      for (const c of condition.conditions) {
        collectExistsTypes(c, map);
      }
      break;
    case 'simple':
      break;
  }
  return map;
}
```

Place this function after the existing `RUST_EXISTS_NAME_RE` constant (around line 73).

Import `Condition` type from `../../../../zero-protocol/src/ast.ts` (add to existing AST import).

Then in the `#addQuery` method, before the `buildPipeline` call (~line 479), add:
```typescript
const existsTypes = collectExistsTypes(resolvedQuery.where);
```

Finally, change line 507 from:
```typescript

```
to:
```typescript
existsTypes.get(relationshipName) ?? 'EXISTS',
```
