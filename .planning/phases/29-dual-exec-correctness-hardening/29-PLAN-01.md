# Plan 29.1: Dual-Exec Hydration Comparison

<objective>
Add a `#dualExecHydrate()` method to `pipeline-driver.ts` that, when dual-exec is enabled and `USE_RUST_HYDRATION` is true, runs BOTH the Rust and TS hydration paths, compares results via `dualExecCompare`, and yields the TS result as source of truth. This closes the gap where Rust hydration runs with zero correctness verification.
</objective>

<read_first>

  </read_first>

<action>
Add a private generator method `*#dualExecHydrate()` to the `PipelineDriver` class with the same parameters as the current hydration call site (queryID, resolvedQuery, input, primaryKeys, tableSpecs). The method:

1. Calls `this.#rustHydrate(queryID, resolvedQuery)` and materializes the result into `rustChanges: RowChange[]` using `materializeChanges()`.
2. Calls `hydrateInternal(input, queryID, must(this.#primaryKeys), this.#tableSpecs)` and materializes the result into `tsChanges: RowChange[]`.
3. Calls `dualExecCompare('hydrate', tsChanges, rustChanges, this.#lc)`.
4. Yields all items from the returned TS changes array (`yield*`).

The method signature should be:

```typescript
*#dualExecHydrate(
  queryID: string,
  resolvedQuery: ResolvedQuery,
  input: Input,
): Generator<RowChange>
```

Note: `hydrateInternal` needs `input`, `queryID`, `this.#primaryKeys`, and `this.#tableSpecs` — all available as class fields or parameters.
</action>

- It materializes both Rust and TS hydration results into arrays
- It calls `dualExecCompare('hydrate', tsChanges, rustChanges, this.#lc)`
- It yields the TS changes (source of truth)
  </acceptance_criteria>

<action>
Modify the hydration branch at line 623 to add a third path:

```typescript
if (USE_RUST_HYDRATION && companionMeta.length === 0) {
  if (isDualExecEnabled) {
    yield * this.#dualExecHydrate(queryID, resolvedQuery, input);
  } else {
    yield * this.#rustHydrate(queryID, resolvedQuery);
  }
} else {
  yield *
    hydrateInternal(input, queryID, must(this.#primaryKeys), this.#tableSpecs);
}
```

This ensures:

- When `USE_RUST_HYDRATION` is on AND dual-exec is enabled: both paths run, results compared
- When `USE_RUST_HYDRATION` is on but dual-exec is off: Rust-only (existing behavior)
- Otherwise: TS-only (existing behavior)
