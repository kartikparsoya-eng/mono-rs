# v5.0 Streaming — Benchmark Results

Append-only log. NEVER delete prior entries — they are the historical regression
baseline. Each line = one bench run. PR reviewers compare recent lines to spot
regressions.

## Format

Each result line follows this shape:

```
<ISO-timestamp> <bench-name> <metric>=<value> [<extras>] <verdict>
```

Verdicts:

- **PASS**: assertion held within the configured threshold.
- **WARN**: assertion failed by a small margin (within ~50% of threshold) — logged but did NOT throw. Track for trend regressions.
- **FAIL**: assertion failed by a large margin (>2× threshold) — bench threw and CI failed.

## Bench types

- **TTFB-streaming** — Phase 33 PERF-02. Measures time-to-first-RowChange under staggered per-pipeline delays. Threshold: `firstChunkT < 1.5 * minPipelineDelay`.
- **MemPeak-streaming** — Phase 33 PERF-03. Measures peak `rss + heapUsed` for buffered vs streaming hydrate of identical workload (4 pipelines × 2500 rows). Threshold: `streamingPeak * 4 <= bufferedPeak * 1.2`.
