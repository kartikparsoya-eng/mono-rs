# Milestone v3.0: Test Coverage & Correctness Hardening

**Status:** SHIPPED 2026-04-21
**Phases:** 16-19
**Total Plans:** 8 (2 per phase)

## Overview

Close all identified test gaps so the "Rust produces identical output" claim is production-grade. 139 Rust tests passing (81 zqlite-rs + 58 zero-ivm-rs), 39 new integration tests across 9 vitest files.

## Phases

### Phase 16: NOT EXISTS & Join Topology Tests

**Goal**: Close operator coverage gaps — NOT EXISTS support and complex join integration tests.
**Requirements:** OPC-01, OPC-02
**Plans**: 2 plans

**Success Criteria:**

1. `existsType` passed through delegate to Rust exists handler
2. NOT EXISTS filter inverts correctly
3. Multi-level join (parent -> child -> grandchild) tested
4. Sibling joins tested
5. All new tests in separate test files (D-35 compliance)

### Phase 17: Data Type Diversity Tests

**Goal**: Prove Rust path handles all SQLite/JS value types correctly.
**Requirements:** DAT-01, DAT-02, DAT-03, DAT-04
**Plans**: 2 plans

**Success Criteria:**

1. JSON objects and arrays round-trip through Rust predicates
2. NULL values produce identical results to TS
3. Unicode strings work in equality and LIKE comparisons
4. MAX_SAFE_INTEGER, -0, NaN, Infinity handled correctly
5. Mixed-type columns compare correctly

### Phase 18: Concurrency & Rayon Determinism Tests

**Goal**: Prove `rust_advance()` is safe under concurrent access.
**Requirements:** CON-01, CON-02
**Plans**: 2 plans

**Success Criteria:**

1. 10 concurrent pushes produce deterministic output
2. Pipeline added/removed mid-advance handled correctly
3. Rayon thread pool handles concurrent calls without data races
4. No deadlocks under contention

### Phase 19: Edit Semantics Verification

**Goal**: Verify intermediate edit stream correctness.
**Requirements:** EDI-01, EDI-02
**Plans**: 2 plans (rust_fan_out fix + 10 new tests)

**Success Criteria:**

1. Edit stream from Rust matches TS edit-by-edit
2. Insert->update produces [add, edit] correctly
3. Insert->delete produces no output (cancellation)
4. Update->delete produces [remove] with correct old values
5. Edit splits produce correct remove+add pairs

## Milestone Summary

**Key Decisions:**

- rust_fan_out() is the active advance path; rust_advance() has prev-snapshot bug and is unused
- D-35: Never modify existing test files

**E2E Validation:**

- Custom Docker image tested against xyne-spaces E2E suite
- 6 cross-compilation/runtime issues fixed (c_char, busy_timeout, close(), BEGIN CONCURRENT, .node naming, ESM imports)
- Zero-cache healthy throughout; all test failures were browser/auth infra, not Rust IVM

**Technical Debt:**

- rust_advance() prev-snapshot bug not fixed (unused path)
- BEGIN CONCURRENT rewritten to BEGIN IMMEDIATE (loses concurrent writer support)
