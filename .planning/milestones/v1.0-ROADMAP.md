# Milestone v1.0 — Rust SQLite Foundation

**Status**: Complete
**Timeline**: 2026-04-20
**Tag**: `mono-rs/v1.0`

## Summary

Incremental rewrite of zero-cache's performance-critical SQLite layer from TypeScript to Rust via napi-rs. Replaced the hot read path (db.ts → TableSource → Snapshotter) with Rust implementations using a binary buffer protocol that achieves 1.78-1.98x throughput improvement over better-sqlite3.

## Key Accomplishments

1. **Rust napi-rs foundation** — Database + Statement classes replacing db.ts, consumed by 60+ files
2. **Binary buffer protocol** — `allBuf()`/`decodeBuf()` eliminates napi overhead for bulk reads
3. **TableSource queryAll** — IVM data layer hot path in Rust
4. **Snapshotter read methods** — `getRow`, `getRowsBuf`, `changesSinceBuf`, `getRowsMultiBuf` in Rust
5. **Benchmark suite** — 7 assert gates, vsDiff simulation, snapshotter-timing regression gate
6. **Decision-driven skips** — 3 phases skipped via measured benchmarks (D-08, D-14, D-19)

## Performance Results

| Benchmark | Rust/TS Ratio | Notes |
|-----------|---------------|-------|
| allBuf(100 rows) | 1.78x faster | Buffer protocol |
| allBuf(1K rows) | 1.91x faster | Buffer protocol |
| allBuf(5K rows) | 1.98x faster | Buffer protocol |
| vsDiff(1K) composite | 0.93x | Near parity, tighter p99 |
| getRow (single) | 0.50x | napi object overhead |
| INSERT | 0.41x | Write path stays TS (D-13) |

## Key Decisions

| ID | Decision | Rationale |
|----|----------|-----------|
| D-08 | StatementRunner stays TS | Pure delegation, no Rust gain |
| D-13 | Write path stays TS | INSERT 0.41x — napi overhead dominates |
| D-14 | Schema modules stay TS | Already Rust-backed via Phase 1, cold-path |
| D-15 | ChangeProcessor stays TS | Write-heavy, same napi overhead issue |
| D-19 | Bulk loader SKIP | 0.4% napi overhead < 5% threshold |
| D-22 | vsDiff simulation added | Proves composite hot path performance |
| D-23 | Assert gates for regression | 4 thresholds enforced in CI |
